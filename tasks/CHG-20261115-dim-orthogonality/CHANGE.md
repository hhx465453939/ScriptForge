## 0.2 现状审计（实测，逐维拆到数据源）

七维当前子指标构成与数据来源：

| 维度 | 子指标 | 数据源 | 问题 |
|---|---|---|---|
| D1 钩子力 | 钩子加权命中 0.45 / 首句 surprisal 0.30 / 前3句标点 0.25 | 词表 + **token_counts** + 位置 | surprisal 与 D2 的熵同源 |
| D2 信息密度 | 信息单元密度 0.45 / 归一化熵 0.35 / Zipf α 0.20 | 词表 + **token_counts** + **token_counts** | 熵与 Zipf α 同源且强负相关 |
| D3 节奏冲击 | Gini 0.40 / CV 0.35 / 主周期 0.25 | **sent_lengths** ×3 | Gini 与 CV 是同一离散度 |
| D4 情绪驱动 | 波动率 0.28 / 斜率 0.24 / CUSUM 0.20 / 情绪词密度 0.28 | **emotion_valence** ×3 + 词表 | 波动率与 CUSUM 高度相关 |
| D5 说服转化 | 信任锚 / 数字 / CTA 位置 − 合规扣分 | 词表 + 位置 | 相对独立 |
| D6 差异化 | JS 散度（扣噪声地板） | **token_counts** | 与 D2 同源（但为相对量） |
| D7 可复制性 | 马尔可夫熵率 | **structure_states** | 独立 |

**结论（根因）**：同一条数据源被反复计权，等于在 TOPSIS 里给同一件事投多次票。
- `sent_lengths` 一条轴 → 被 D3 用三次
- `emotion_valence` 一条轴 → 被 D4 用三次
- `token_counts` 一条轴 → 被 D1/D2/D2/D6 用四次

**有效独立轴估计：5 条**（长度动态 / 情绪动态 / 词汇分布 / 分类强度 / 序列结构），
而对外口径写「七维」。这不是数值 bug，是**口径不诚实**——用户会以为七个方向独立在打分。

## 0.3 目标形态

1. **维度内去重**：同一维度内不得有两个「同一统计量的不同标度」。换成真正不同的**方面**（aspect）。
2. **跨维降耦**：把 D1 从「词汇」轴移到「位置」轴，让它不再与 D2 共源。
3. **提供审计工具**：输出源依赖矩阵（精确、无需数据）+ 相相关矩阵 + 特征值谱 + 有效维度估计，让人**能自己验证**而不是听我说。
4. **口径对齐**：实现、文档、README、manifest 四处口径一致，不许一处说七维独立、另一处承认共线。

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| 去重后维度信息量下降 | 每个被替换项都换入**不同方面**的新测度，不是简单删除；并在 TRACEABILITY 记录替换理由 |
| 分数整体位移引发"是不是坏了" | 在 TRACEABILITY 记三形态改前改后分数 + 变化原因，明示是口径修正不是抖动 |
| 新测度在小样本上不可靠 | `alternation_rate` 与 `peak_position` 都给最小样本门与可靠标记 |
| 审计工具用 n≈12 语料算相关不可靠 | 工具**强制输出样本量警告**；相关系数只作健全性检查，不作结论；源依赖矩阵才是精确结论 |
| 口径改了但文档漏改 | SPEC 交付清单强制列 4 处口径文件，验收命令 grep 校验 |

## 3. 成功判据

1. 每个维度内不存在「同一统计量的两个标度」（源依赖矩阵自检通过）
2. `python scripts/dim_audit.py` 输出源依赖矩阵 + 相关矩阵 + 有效维度，且带样本量警告
3. 三形态评分可跑通，分数变化在 TRACEABILITY 有记录与解释
4. 实现/`math-engine.md`/`SKILL.md`/README/manifest 五处口径一致
5. 全量单测通过（含新增正交性测试）
