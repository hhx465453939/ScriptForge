# CHANGE：从「视频文案单形态」到「多形态内容拆解」

- change_id: CHG-20261115-multimodal-decompose
- 提出人: Owner
- 提出时间: 2026-11-15
- 状态: approved
- 关联 CHG: CHG-20261115-viralmath-engine（下游引擎，本 CHG 产出其输入形态）

---

## 0.1 原始需求（Owner 原话）

> 这个项目加一个功能，就是除了视频文案拆解，还可以做文本和图文内容的拆解，并根据用户主题输出新的爆款。

## 0.2 现状审计（实测）

| 事实 | 证据 |
|---|---|
| 入口只认「视频口播文案」 | `SKILL.md` L5 description 写「接收任意行业的短视频文字脚本」；「快速启动」第 1 条「确认文案内容完整」隐含口播稿 |
| 五层拆解全部为口播设计 | 「钩子雷达」12 类钩子（痛点/利益/悬念…）无一种是图文专属（标题党公式、首图视觉钩、封面文字钩） |
| 骨架框架库 8 种全为口播 | `references/workflow-guide.md` §2.2：带货五段式/AIDA/PAS/FAB/故事弧/清单体/测评体/吐槽安利 |
| 无「形态」概念 | 全库 grep `图文`/`笔记`/`纯文本`/`长文` → 仅 `platform-insights.md` 出现「视频笔记」一词，无拆解规则 |
| 模型库 3 个模型全是口播 | `references/script-models.md`：吐槽安利/痛点暴击/清单收割，完形填空骨架均为口语流水句 |
| 完形填空只覆盖口播 | `references/fill-blank-guide.md` 无标题/首图/正文分段/标签位规则 |
| 输出 9 板块固定 | `SKILL.md`「标准输出结构」无图文/文本分支 |

**结论（根因）**：项目把「视频口播」这个**形态**当成了**唯一形态**写进了所有层级。新增图文/文本不是加一个分支，而是要引入「形态（genre）」这个正交维度，并在 7 处（入口判定/钩子库/骨架库/逻辑链/亮点/评估/完形填空）全部形态化。

## 0.3 目标形态

用户丢进来任何一段内容 → 系统先判定形态（视频口播 / 图文笔记 / 纯文本长文）→ 按该形态的专属拆解矩阵执行 → 归结到统一的「可复用模型 + 完形填空」→ 按用户主题输出新爆款。

---

## 1. 范围

### 1.1 In Scope

| 形态 | 典型载体 | 最小启动条件 |
|---|---|---|
| video（视频口播） | 抖音/快手/视频号口播稿 | 完整口播文案 |
| graphic（图文笔记） | 小红书笔记、公众号图文、头条图文 | 标题 + 正文（首图描述可选） |
| text（纯文本长文） | 知乎回答、公众号长文、微博、朋友圈 | 标题（可选）+ 正文 |

### 1.2 Out of Scope

- 不做图片/视频的实际解析（无 OCR / 无视频抽帧）——图文首图只接受用户**文字描述**
- 不做自动抓取平台数据（保持 MCP 为可选辅助）
- 不改动既有 3 个口播模型的定义与骨架（只做兼容标注）
- 不引入任何第三方 Python 依赖（保持 skill 零依赖可移植）

---

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| 形态误判导致用错拆解矩阵 | 判定规则给「强信号 → 弱信号」两级，并在输出首行显式声明判定结果 + 置信度，允许用户一键覆盖 |
| 三种形态规则互相污染，文档膨胀 | 单文件 `references/content-genres.md` 集中承载形态矩阵；workflow-guide 只做路由，不复制规则 |
| 图文拆解退化成「口播规则换名词」 | 每形态必须有其**专属**可直接量化的特征项（如图文：标题字数区间、emoji 密度、分段数、标签数） |

## 3. 成功判据（验收基线）

1. 给定一条小红书图文笔记（含标题+正文），无需用户额外说明，系统自动走 graphic 矩阵，输出含「标题公式拆解 / 首图钩子 / 分段节奏 / 标签策略」的完整报告。
2. 给定一条公众号长文，自动走 text 矩阵，输出含「论点链 / 论证结构 / 金句密度」的报告。
3. 三种形态都能产出该形态的完形填空模板（图文含标题公式位、标签位）。
4. 既有视频口播流程行为不变（回归零破坏）。
