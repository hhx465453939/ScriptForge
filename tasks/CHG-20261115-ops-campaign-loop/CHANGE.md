## 0.1 原始需求（Owner 原话）

> 爆款的定义，很简单，就是流量，阅读量，播放量，如果是产品就是销量，如果是这个项目，开源项目，那就是 star 数等等，这些东西都是指标……我理解你的意思，就是在项目内部，把流量管理的完整闭环建立起来……我们这个项目，要的不是做出爆款，而是搭台子，给工具，然后纳入人和 agent 的要素，让有能力运营的人坐上飞机，让运营新手坐在副驾（主驾驶可以自动驾驶，就是这个项目的框架和台子提供的优秀方法论引导 agent 进行优质回复）。
>
> 我把这个开发好的项目，部署在 openclaw 上，然后跟 agent 说：「帮我把部署给你的这个项目想办法运营火，给我文案，我来做视频和图文，我们一起来证明这个项目的价值。」然后 agent 就会去想尽办法去搜索信息（无论有没有部署专业的自媒体信息与数据 mcp），然后根据自己的数据，以及这个项目的特点，给我文案，策略，近期热点概念分析报告，图片，html 设计文件，文生图，文生视频提示词 + 适配平台 + 模型等等所有文件在内的完整运营物料包。

## 0.2 现状审计（实测）

| 事实 | 证据 |
|---|---|
| 链路是**单向**的 | `workflow-guide.md` Phase 0→6：形态判定→拆解→模型→完形填空→仿写→知识分享。结束即结束，无回填 |
| **没有「目标」概念** | 全库无「主指标 / 目标对象 / 成功判据」定义。skill 不知道用户要的是播放量、销量还是 star |
| **没有物料层** | 只产出文案。图片、HTML、文生图提示词、文生视频提示词、平台适配——全部缺失 |
| **没有排期** | `assets/calendar-template.md` 是完形填空示范，不是发布排期 |
| **没有回填** | 无任何字段用于回收真实指标 |
| **没有校准触发** | `math-engine.md` §7 写了 7 步校准协议，但没有任何机制触达它 |
| 侦察能力停留在「可选 MCP」 | `mcp-reference.md` 仅 28 行，无降级链、无来源分级强制、无热点分析方法 |
| 「爆款」无量化定义 | 全库无「多少算爆」的判据 |

**结论（根因）**：项目把「内容生产」误当成「运营」。内容生产是运营的**一个环节**，不是全部。缺的是三层：
1. **目标层**：为谁、要哪个指标、多少算赢
2. **物料层**：一条策略 → 一整套可发布资产（文案/图/视频/网页/提示词/平台参数）
3. **反馈层**：发布 → 数据回填 → 判断假设对错 → 校准模型

没有第三层，前两层永远无法变聪明。

## 0.3 目标形态

把项目从「文案拆解器」升级为 **运营作战台**：

```
给定一个目标（项目/产品/账号）+ 主指标
  → 侦察（受众/竞品/热点，带来源分级）
  → 定位（差异化 + 不做什么）
  → 选题池（多维打分排序）
  → 生产（多形态文案 + 量化评分卡）
  → 组装（图/视频/HTML/提示词/平台×模型适配）
  → 排期
  → 回填（真实指标）
  → 校准（更新基线/权重/假设结论）
  → 回到侦察
```

三个硬要求：
1. **指标先行**：任何 campaign 必须先声明 `主指标`，否则不许开工
2. **物料齐全**：交付物是**目录**不是段落，缺件即不合格
3. **闭环可回填**：每份物料都能对应到回填表的一行

## 1. 范围

### In Scope
- 指标族与「爆」的量化判据（按目标对象分档）
- S0–S8 八阶段闭环 + 阶段门控
- 三档协作模式（主驾 / 副驾 / 自动驾驶）
- 运营物料包**目录契约**与每份文件的最小规格
- 文生图 / 文生视频**提示词字段冻结** + 平台×模型适配矩阵
- 侦察协议（数据源降级链 + 来源分级强制）
- 回填台账 + 假设台账
- `scripts/campaign_init.py` 一键生成物料包骨架

### Out of Scope
- 不实现真实爬虫/API 采集（只定义协议与降级链，执行交给 MCP/搜索工具）
- 不生成实际图片/视频文件（只产出**提示词与规格**，生产由用户或下游工具完成）
- 不接入平台后台 API（回填由用户手动填表，后续再谈自动化）
- 不做数据看板 / BI
- 不改动既有拆解规则、形态矩阵、量化引擎逻辑

## 2. 风险与对策

| 风险 | 对策 |
|---|---|
| 「自动驾驶」被误解为「agent 可以乱发内容」 | 明确 autopilot 也必须在 3 个决策点请求确认：目标指标、资源边界、发布前终审。**永不代发** |
| 物料包变成堆文件、没有规格约束 | 每份文件在 `assets/campaign-package.md` 里有**最小规格**与**缺件判定**，缺件即不合格 |
| 指标定义又变成拍脑袋 | 判据统一为「主指标 ≥ 同条件历史 P80」，且必须带区间；无历史时标 `BASELINE_MISSING` 并降级为观测模式 |
| 提示词写成散文，无法复用 | 字段冻结（subject/scene/composition/...），缺字段即不合格 |
| 门控太严导致 agent 无法产出 | 门控只拦「跳过证据」的产出，不拦「标注了缺失」的产出；缺失必须显式写 `UNKNOWN` 而不是编造 |
| 与既有 skill 职责重叠 | 视觉设计交给 `taste` skill，信息检索交给 deep-research/MCP；本 CHG 只做**协议与契约** |

## 3. 成功判据

1. 给定「把这个开源项目运营火」，agent 按 `ops-loop.md` 走完 S0–S8，产出 `campaigns/<slug>_<date>/` 目录下 **10 类文件齐全**
2. 每份文案带量化评分卡（七维 + 综合分 + 95% CI）
3. 每份物料带「平台 × 模型」适配标注
4. 回填表可填，且填完能触发校准检查（`07-ledger.md` → `08-review.md`）
5. 既有 79 项单测与三形态评分结果零变化
