# 数据回填台账 与 假设台账

> 本文件是运营作战台的**反馈层**。没有这一层，前面八个阶段全部白做——因为你永远不知道自己做对了什么。
>
> 一句话：**回填是唯一能证伪自己的动作。**

---

## 1. 回填表（`07-ledger.md`）

### 1.1 字段（与 `references/metrics-taxonomy.md` §4 对齐）

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `row_id` | ✅ | string | 唯一行号，建议 `L001` 起 |
| `campaign` | ✅ | string | campaign slug |
| `asset_file` | ✅ | string | 对应 `04-scripts/` 或 `05-assets/` 的文件名 |
| `platform` | ✅ | string | 实际发布渠道 |
| `published_at` | ✅ | date | **实际**发布日（不是计划日） |
| `primary_value` | ✅ | number | 主指标数值 |
| `secondary_values` | ✅ | object | 辅助指标键值对 |
| `window` | ✅ | object | `{start, end}` 观测窗口 |
| `source_level` | ✅ | `L1`\|`L2`\|`L3` | 数据来源层级 |
| `baseline_at_publish` | ✅ | object | 发布时的基线快照 |
| `hypothesis_id` | ✅ | string | 要验证的假设编号 |
| `notes` | ⬜ | string | 异常说明（限流/违规/撞热点） |

**两条红线**：

1. `source_level` 为空或写 `L3` 时，**不得**用于「爆/不爆」判定，只能记录
2. `baseline_at_publish` 必须是**发布当时**的快照；事后补填等于给自己作弊

### 1.2 表模板

```markdown
| row_id | asset_file | platform | published_at | primary | secondary | window | source | baseline_at_publish | hyp | notes |
|---|---|---|---|---|---|---|---|---|---|---|
| L001 | graphic-01.md | xiaohongshu | 2026-11-18 | 3200 | {收藏:210, 互动率:"4.1%"} | {11-18,11-21} | L1 | {p80: 2800, n: 12} | H1 | — |
| L002 | video-01.md | douyin | 2026-11-19 | 8100 | {完播:"31%"} | {11-19,11-22} | L1 | {p80: 9500, n: 9} | H2 | 撞热点，需标记 |
```

### 1.3 回填纪律

| 纪律 | 原因 |
|---|---|
| 发布后 **72 小时内**回填首轮 | 多数平台流量 3 天内定型，晚了会漏掉峰值 |
| 同一行只允许一个观测窗口 | 混窗口 = 无法比较 |
| 数据缺失写 `UNKNOWN`，不许留空 | 留空会被误读为 0 |
| 变体必须分行记录 | 否则无法归因到具体变量 |

## 2. 假设台账（`07-ledger.md` 下半部）

### 2.1 为什么需要它

拆解能产出「结构特征」，但**特征不等于规律**。规律必须写成**可证伪的句子**，否则永远只是观感。

假设模板（一句话，含三个部件）：

```
H<编号>: 若 <改动>，则 <主指标> 会 <方向>，因为 <机制>。
```

正例：
- `H1: 若把首句改为冲突钩（如「哑巴能不能不要当设计师」），则 xiaohongshu 收藏率会上升，因为冲突制造信息缺口，逼读者看完再判断。`
- `H2: 若标题从 22 字压到 16 字，则点击率上升，因为信息流只显示前 15 字。`

反例（不可证伪，禁止）：
- ❌ 「内容要更有共鸣」——没有改动、没有指标、没有方向
- ❌ 「多发就会火」——不可证伪

### 2.2 台账表

```markdown
| hyp_id | 假设句 | 变量（只改这个） | 对照 row_id | 结果 row_id | 结论 | 证据强度 |
|---|---|---|---|---|---|---|
| H1 | 若首句改冲突钩，则收藏率↑，因为信息缺口 | 首句 | L001 | L003 | 支持 | 中（n=2） |
| H2 | 若标题压到 16 字，则点击率↑ | 标题 | L002 | L004 | 被否证 | 中（n=2） |
```

`结论` 只能填三值：`支持` / `被否证` / `证据不足`。
`证据强度`：`强（n≥10 且区间不重叠）` / `中（n≥5）` / `弱（n<5）`。

**严禁**把「证据不足」写成「支持」。这是整个闭环最容易被污染的地方。

### 2.3 假设从哪来

| 来源 | 例子 |
|---|---|
| S2 定位的差异点 | 「我们不卖焦虑」→ 假设：反焦虑开头会提高完播 |
| S4 评分卡的短板 | 情绪驱动 0.34 → 假设：插入具体场景后情绪分会升、互动会升 |
| 竞品观察 | 竞品都用数字标题 → 假设：数字标题在小红书更吃香 |
| 平台洞察 | `platform-insights.md` 的定性结论 → 变成可检验句 |

## 3. 校准触发条件（S7 → S8）

回填完成后，按下列条件判断能不能进 S8：

| 条件 | 门槛 | 不满足时 |
|---|---|---|
| 有效回填行数 | ≥ 3 | 只能写「样本不足，暂不校准」 |
| 至少 1 组对照 | 1 条假设有 2 个以上 row | 只能做描述性统计，不能验假设 |
| `source_level` 为 L1/L2 的比例 | ≥ 50% | 结论标注「低可信」 |
| 观测窗口完整 | 全部已过窗口末日 | 未到期行标 `PENDING` |

## 4. 校准动作清单（S8 必须逐项打勾）

- [ ] **判定**：按 `metrics-taxonomy.md` §2 算 P80 与该条分位 → 爆/未爆（n<10 只给相对位置）
- [ ] **验假设**：逐条给 `支持/被否证/证据不足`，附证据强度
- [ ] **重估基线**：并入新数据，重算 `{p50, p80, n}`，写入下一轮 `00-brief.md`
- [ ] **改尺子（谨慎）**：若某维度与实际结果长期不相关，标「本维度待重估」——**一次只允许改一项**
- [ ] **回流三件事**：
  - [ ] 更新下一轮基线
  - [ ] 把「被否证的假设」写进下一轮 S2 的注意事项
  - [ ] 把「超预期的结构」补进 `references/script-models.md` 的「已验证品类」

## 5. 反模式

| 反模式 | 后果 |
|---|---|
| 只回填主指标，不回填辅助指标 | 爆了不知道为什么爆，无法复制 |
| 小心地把「证据不足」写「支持」 | 闭环污染，越跑越偏 |
| 事后修改 `baseline_at_publish` | 等于改考卷分数 |
| 一次改多个变量再比较 | 无法归因 |
| 无回填就写复盘 | 复盘变成自我安慰 |
| 用 `L3` 数据下「爆/不爆」结论 | 违反 `metrics-taxonomy.md` §5 硬规则 |

## 6. 第一次跑：没有基线的做法

1. `00-brief.md` 写 `baseline: BASELINE_MISSING`
2. 本 campaign 定位为**基线采集战役**：目标是产出 `n ≥ 10` 的有效样本，而不是"爆"
3. 发布 10–15 条（覆盖 2–3 个形态 × 2 个渠道），全部回填
4. `08-review.md` 第一步：算出 P50/P80 写入基线
5. 下一轮才具备「判定爆/不爆」的能力

**这一步不能跳。** 跳过就等于回到拍脑袋。
