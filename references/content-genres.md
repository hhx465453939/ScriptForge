# 多形态内容拆解矩阵（video / graphic / text）

> **本文件是三形态差异规则的唯一承载点。** 其他文件只允许「引用 + 路由」，禁止复制第二份规则。
> 改形态规则只改这里。
>
> 核心主张：**形态不是分支，是正交维度。** 同一套「钩子→结构→说服→亮点→评估→完形填空」骨架，
> 在不同形态下要用不同的**可量化特征**去读。口播的杀手锏是前 3 秒，图文的是标题与首图，
> 长文的是论证与可检索性。用口播规则去套图文，等于用体温计量身高。

---

## 1. 三形态速览

| 维度 | video 视频口播 | graphic 图文笔记 | text 纯文本长文 |
|---|---|---|---|
| 典型载体 | 抖音/快手/视频号口播稿 | 小红书笔记、公众号图文、头条图文 | 知乎回答、公众号长文、微博、朋友圈 |
| 消费单位 | 3 秒 | 1 张首图 + 标题 | 前 3 段 |
| 决定生死的位置 | 前 3 秒（完播率池） | 标题 + 首图（点击率） | 首段结论 + 小标题（跳读） |
| 平台核心指标 | 完播率 > 互动率 > 转化 | 收藏率 > 互动率 > 搜索相关性 | 读完率 > 收藏 > 长尾搜索 |
| 最小启动条件 | 完整口播文案 | 标题 + 正文（首图描述可选） | 标题（可选）+ 正文 |
| 节奏来源 | 语速 + 长短句交替 | 分段密度 + emoji + 空行 | 小标题切分 + 段落长度 |
| 完形填空的重点 | 开头钩子句 + CTA 句式 | 标题公式 + 分段骨架 + 标签位 | 论点链 + 论证句式 |
| 引擎权重最高维度 | 钩子力 / 节奏冲击 | 钩子力 / 差异化 | 说服转化 / 可复制性 |

## 2. 形态判定（对应 SPEC-A §4，冻结）

判定只看文本本身，按优先级**短路**（命中即停）。实现：`scripts/genre_probe.py`。

| 优先级 | 信号 | 判定 | 置信度 |
|---|---|---|---|
| 0 | 用户显式声明（「这是小红书图文」） | 用户指定，覆盖一切 | 高 |
| 1 | 含 `口播`/`镜头`/`前3秒`/`旁白`/`字幕`/`分镜`/`第1秒` | video | 高 |
| 2 | 含 `#话题#` 或 `@用户` | graphic | 高 |
| 3 | 首行 ≤25 字 + emoji ≥3 + ≥3 行分列 | graphic | 中 |
| 4 | 含 `##`/`一、二、`/`图1`/`表1`/`参考文献` | text | 中 |
| 5 | 口语称呼 ≥2（姐妹们/老铁/宝子/你们/咱）+ 平均句长 ≤15 | video | 中 |
| 6 | 兜底：平均句长 ≤20 且 ≤5 段 → video，否则 text | — | **低** |

### 2.1 置信度处理纪律

- **高**：直接按该形态执行，无需询问
- **中**：执行，但在报告首行声明判定结果与依据
- **低**：执行，但**必须**提示用户可覆盖，例如：
  > 形态判定为 text（置信度：低，兜底规则命中）。如果你要按图文拆解，请告诉我「这是图文」。

### 2.2 用户覆盖

用户说任何形如「这是图文 / 按长文拆 / 当口播处理」的话 → 立即以用户指定为准，不再自动判定。
引擎侧对应 `--genre graphic|text|video`。

## 3. 形态专属拆解矩阵

通用层（8 板块）三形态共用：`基础判断 / 钩子拆解 / 结构解码 / 说服逻辑链 / 亮点标注 / 爆款潜力评估 / 完形填空模板 / 仿写脚本`。
下列是**形态专属层**，每项都是**能数出来的**，不许写形容词。

### 3.1 video · 专属层

#### 板块 A：钩子时间轴

| 量化项 | 怎么数 | 参考区间（CALIBRATION_PENDING） | 为什么重要 |
|---|---|---|---|
| 前 3 秒字数 | 前 3 句有效字数合计 | 25–60 字（约 3 秒口播量） | 超 60 字 = 3 秒说不完，钩子被截断 |
| 首句问号/感叹号 | 前 3 句 `？!` 计数 | ≥1 | 疑问/惊叹是留人开关 |
| 首句是否含冲突词 | `冲突钩` 词表命中 | 命中即加分 | 「能不能不要」类反转最抓人 |
| 钩子类型覆盖数 | 前 3 句命中的钩子类型种数 | 1–2 种 | 3 种以上会互相打架，信息过载 |

#### 板块 B：口播节奏

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 平均句长 | 有效字数 / 句数 | **≤15 字** | 超过 20 字口播会喘不上气 |
| 句长 Gini | 引擎 `rhythm.gini` | 0.25–0.45 | 长短交替才有节拍 |
| 感叹号数 | `！` 计数 | 2–6 | 0 = 平淡；>8 = 吼叫 |
| 第二人称出现次数 | `你/您` 计数 | ≥3 | 对镜头说话才有代入感 |
| CTA 相对位置 | 引擎 `cta_position_ratio` | 0.75–0.95 | 太早催单会掉完播 |

**video 特有反模式**：书面语连接词（「因此」「综上所述」「基于此」）→ 口播必改口语。

### 3.2 graphic · 专属层

#### 板块 A：标题公式

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 标题字数 | 有效字数 | **12–18 字**（>20 字点击率明显下滑） | 信息流里只显示前 15 字左右 |
| 标题公式类型 | 引擎 `title_formula`：数字清单/反差打脸/人群圈定/痛点提问/稀缺限定/权威背书 | 命中 1 种，最好「人群 + 痛点 + 爽点」叠加 | 公式决定点击动机 |
| 标题是否含数字 | 阿拉伯数字或中文数字 | 建议含 | 数字降低认知成本 |
| 标题是否含人群词 | 党/人/族/宝妈/打工人 | 建议含 | 精准圈人提高点击率 |

**标题公式速查**

| 公式 | 结构 | 示例骨架 |
|---|---|---|
| 数字清单 | 数字 + 品类 + 价值 | 「3个让我多睡20分钟的___」 |
| 反差打脸 | 预期违背 + 结果 | 「以为是智商税，结果真香」 |
| 人群圈定 | 人群 + 场景 + 必备 | 「早八人必备的___」 |
| 痛点提问 | 为什么/怎么 + 痛点 | 「为什么你的___总是___？」 |
| 稀缺限定 | 限时/最后 + 品类 | 「最后一波___，错过等一年」 |
| 权威背书 | 亲测/实测 + 结论 | 「亲测一个月，终于不___了」 |

#### 板块 B：首图钩子（用户提供文字描述时）

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 首图文字字数 | 描述里标注的画面文字 | **≤12 字** | 首图文字超过 12 字在信息流里看不清 |
| 首图是否有对比 | 出现「前后/对比/左/右」 | 建议有 | before/after 是最高点击形态 |
| 首图是否有结果承诺 | 出现具体结果词 | 建议有 | 「28天」比「坚持」强 |
| 首图与标题关系 | 互补 or 重复 | **互补** | 完全重复 = 浪费一个钩子位 |

#### 板块 C：分段节奏

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 段落数 | 空行切分 | **3–8 段** | <3 显得敷衍，>8 移动端划不完 |
| 单段行数中位数 | 引擎 `median_lines_per_para` | **1–3 行** | 大段文字在小红书必被划走 |
| 平均段字数 | 有效字数 / 段数 | 30–80 字 | 一段一个信息点 |
| emoji 数 | 引擎 `emoji_count` | 每 100 字 2–5 个 | 是分段标记与情绪标记；>10 个显得杂乱 |
| 是否有空行分隔 | 连续两个换行 | 建议有 | 移动端留白 = 可读性 |

#### 板块 D：标签策略

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 标签数 | `#xxx` 计数 | **4–8 个** | <3 搜索流量拿不到，>10 会被判堆砌 |
| 标签类型覆盖 | 品类词 / 人群词 / 场景词 / 长尾词 | 至少覆盖 3 类 | 单类型标签吃不到长尾 |
| 是否含 1 个大词 | 品类核心词 | 建议含 1 个 | 大词拿曝光，长尾拿精准 |
| 标签与正文一致性 | 正文是否出现同义内容 | 建议一致 | 标签与内容不符会被降权 |

**graphic 特有反模式**：正文写成口播流水句（一逗到底、没有分段）；标题与首图说同一句话。

### 3.3 text · 专属层

#### 板块 A：论点链（claim → evidence → qualifier）

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 论点句数 | 引擎 `claim_count`（结构标记命中句） | 2–6 个 | 长文没有明确论点=读者没有抓手 |
| 证据/论点比 | 引擎 `evidence_ratio` | **≥1.0** | 每个论点至少 1 条证据，否则是空谈 |
| 是否有限定语 | `hedge` 词（可能/一般来说/样本有限） | ≥1 处 | 无条件断言会招反驳与举报 |
| 论点是否前置 | 首段是否含结论 | 建议前 3 段内出结论 | 长文读者是跳读的 |

**论点链标注格式**

```
C1 [主张] 标题长度与点击率负相关
  E1 [证据] 实测 200 条笔记，>20 字点击率下降约三成
  Q1 [限定] 样本有限，且平台算法会迭代
```

#### 板块 B：论证结构

| 结构 | 特征 | 适用 |
|---|---|---|
| 总分总 | 结论 → 分点论证 → 回收结论 | 观点输出类（最稳） |
| 问题—归因—方案 | 现象 → 为什么 → 怎么办 | 干货教程类 |
| 反驳—回应 | 先立反方观点再拆解 | 争议话题类（互动高） |
| 递进式 | 每节建立在上一节之上 | 深度长文 |

#### 板块 C：金句密度

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 金句密度 | 引擎 `golden_sentence_per_kchar`（每千字金句句数） | **2–6 / 千字** | 是转发与引用的抓手 |
| 金句位置 | 出现在段尾/文末最佳 | 建议每节末尾或文末 | 段尾句最容易被记住 |
| 金句结构 | 是否有「不是A，而是B」「与其A，不如B」对偶 | 建议有 | 对偶句最易传播 |

#### 板块 D：长文钩子

| 量化项 | 怎么数 | 参考区间 | 为什么重要 |
|---|---|---|---|
| 小标题数 | 引擎 `heading_count` | 每 800–1200 字 1 个 | 小标题是跳读者的路标 |
| 首段字数 | 第一段有效字数 | **≤120 字** | 首段太长读者直接退出 |
| 首段是否给结论 | 结论关键词是否出现在首段 | 建议是 | 长文先给结论再论证 |
| 段数 | 引擎 `para_count` | 8–30 段 | 单段超过 5 行必被跳过 |

**text 特有反模式**：开头写「随着……的发展」；全篇无小标题；结尾无结论回收。

## 4. 形态 × 量化引擎对接

引擎的 7 个维度在三形态下的**主要来源特征**（其余特征仍参与计算）：

| 引擎维度 | video 主要来源 | graphic 主要来源 | text 主要来源 |
|---|---|---|---|
| 钩子力 `hook` | 前3秒钩子词 + 首句 surprisal | 标题公式 + 首图描述 + 首段钩子 | 首段结论 + 标题提问 |
| 信息密度 `density` | 每百字信息单元 | 每百字信息单元 + emoji 分段 | 每百字信息单元 + 证据密度 |
| 节奏冲击 `rhythm` | 句长 Gini + 主周期 | 段落节奏 + 段长变异 | 小标题间隔节奏 |
| 情绪驱动 `emotion` | 情绪序列波动 + 转折 | 情绪词 + emoji 情绪 | 语气起伏（较弱） |
| 说服转化 `persuasion` | 信任锚 + CTA 位置 | 信任锚 + 标签精准度 | 论证强度 + 证据比 |
| 差异化 `distinction` | 用词偏离 | 用词偏离 + 视觉差异 | 观点新颖度（词面弱代理） |
| 可复制性 `replicability` | 结构状态转移 | 分段骨架固定度 | 论证结构固定度 |

**跨形态比较禁令**：三形态 AHP 权重档不同、基线语料不同，**绝对分不可跨形态比较**。
只能说「这条在它自己的形态里处于 B 区」，不能说「这条比那条好」。

## 5. 主题驱动生成（用户给主题 → 产出新爆款）

当用户说「帮我写一条关于 ___ 的爆款（图文/长文/口播）」时，按以下流程：

```
1. 定形态      → 用户指定优先；未指定则按发布平台推断并声明
2. 选模型      → 从 references/script-models.md 按「形态标签」匹配
3. 定权重重点  → 查 engines 的 priority_dimensions_for_genre，先保该形态高权重维度
4. 套完形填空  → 用该模型的骨架，按形态规则填
5. 量化自检    → 跑 python scripts/viral_score.py --text "<成品>" --genre <形态>
6. 定点迭代    → 只看 weaknesses 前 2 项，针对性改，再跑一次
7. 交付        → 输出成品 + 所用模型名 + 量化分区 + 短板与已做的修改说明
```

**第 5–6 步是硬要求**：不许说自己写得好，必须跑出数字。交付格式见 `assets/quant-scorecard-template.md`。

输出模板：

```
形态：graphic（小红书图文）
套用模型：人群圈点（见 script-models.md 模型 5）
量化分区：B（58.4，95% CI 51.2–65.0）
已针对性修补：标题 22 字 → 16 字；段落 11 段 → 6 段
剩余短板：情绪驱动 0.34（正文无具体痛点场景）→ 建议第 2 段插入一个真实使用场景
```

## 6. 完形填空的形态差异

完形填空（`references/fill-blank-guide.md` 是规则主文件）在三形态下的差异：

| 形态 | 必须保留 | 必须留空 | 特有占位位 |
|---|---|---|---|
| video | 转折词、情绪句式、CTA 句式、节奏 | 产品名、卖点、数据、价格 | `[______旧方案]`、`[______负面结果]` |
| graphic | 标题公式、分段骨架、emoji 位置、标签类型 | 品类名、人群词、场景、卖点 | `[______标题公式槽]`、`[______首图钩子]`、`[______标签组]` |
| text | 论点句式、论证结构、限定语、金句对偶 | 论题、证据数据、结论动词 | `[______主张]`、`[______证据]`、`[______限定条件]` |

图文模板必含 **4 个特有位置**（SPEC-A G3 验收）：标题公式位、首图钩子位、正文分段位、标签位。
