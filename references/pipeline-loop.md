# Pipeline 模式 · 个人生产流水线

> **本文件是 B 入口（运营）的唯一流程承载点。**
> 取代 `references/ops-loop.md` 的 S5–S8；S0–S4 的决策价值保留，但**不再落成独立过程文件**。
>
> 一句话区别：
> **campaign 模式是「给团队交付物料包」，pipeline 模式是「给工具交付参数」。**

## 0. 为什么砍掉过程文档

| 旧产物（campaign） | 在新模式里的下场 |
|---|---|
| `00-brief.md` 目标书 | 压成 `README.md` 里 2 行 |
| `01-recon.md` 侦察报告 | **保留动作**，结论压成选题理由 1 行 |
| `02-positioning.md` 定位 | 压成 1 行（差异点） |
| `03-backlog.md` 选题池 | 内部推理，不落文件 |
| `04-scripts/` 文案 | **保留并强化**——这是唯一的核心产出 |
| `05-assets/` 组装 | 并入文案阶段，直接产参数 |
| `06-schedule.md` 排期 | **删除**。`--publish-at` 一行参数就够了 |
| `07-ledger.md` 台账 | **删除**。改为 MCP 自动回读 |
| `08-review.md` 复盘 | 压成一页回读 |

**理由**：这些文件的原始用途是**协调多人**。个人流水线里，
协调由工具链本身完成（文案 → MPT → MatrixMedia → 数据），中间文档只剩两个作用：
稀释注意力、制造虚假完备感。

## 1. 五阶段流程（冻结）

```
P0 定标（轻）
  → P1 侦察 + 选题（保留，结论内联）
    → P2 写稿（核心 · 注意力主战场）
      → P3 出参数（与 P2 紧邻，产出可执行物）
        → P4 回读（MCP 自动拉数据，一页）
```

### P0 定标（输出：`README.md` 前 3 行）

```markdown
目标：<平台> 的 <主指标>（如 抖音播放量 / 小红书收藏）
定位：<一句话差异点>
本轮选题：<2–3 条，每条一句理由>
```

**不要**写满一页战略。超过 5 行就是在稀释注意力。

**门控 P0**：没有主指标 → 不进入 P1。

### P1 侦察 + 选题（输出：内联进 `README.md`）

| 动作 | 产出 | 纪律 |
|---|---|---|
| 受众 / 竞品 / 热点扫描 | 结论 ≤3 条 | 每条带来源层级 `L1/L2/L3`；拿不到写 `UNKNOWN` |
| 选题排序 | 2–3 条，带一句理由 | "我觉得会火"不算理由 |

**门控 P1**：无来源层级的结论不许用。

### P2 写稿（核心）

| 步骤 | 做法 |
|---|---|
| 1 定形态 | `content-genres.md` §2 判定 video / graphic / text |
| 2 选模型 | `script-models.md` 现有 7 个模型中选 |
| 3 套骨架 | `fill-blank-guide.md` |
| 4 **量化自检** | `python scripts/viral_score.py --file <稿> --json` |
| 5 定点迭代 | 只改 `weaknesses` 前 2 项，再跑一次，记变化 |

**门控 P2**：无评分卡 → 不进入 P3。

**注意力纪律（本 CHG 的核心）**：
- 一次只写 1–3 条，不许一次铺 10 条
- 每条必须跑出分数，**不许手写分数**
- 迭代记录只记「改了什么 → 分数怎么变」

### P3 出参数（与 P2 紧邻）

| 平台 | 产出 | 依据 |
|---|---|---|
| 抖音 / 快手 / 视频号 / B站 / 头条 / 百家号 | `script.md` + `mpt.json` + `publish.sh` | `references/downstream-contracts.md` §1/§2 |
| 小红书（图文） | `note.md` + `cover-prompt.md` + `publish.md` | 同上 §2.4（**图文不可自动分发**） |
| 公众号 | `article.html` + `header-prompt.md` + `publish.md` | 同上 §2.4 |

**参数三铁律**：
1. 字段名只能来自 `downstream-contracts.md` 表里有的
2. 不确定写 `UNKNOWN`，不猜
3. `-f` 视频路径未生成时写占位 `<待填：...>`，不填假路径

**门控 P3**：`mpt.json` 键名不在契约表内 → 重写；图文生成了 `cli publish` → 重写。

### P4 回读（替代旧 S7/S8）

| 步骤 | 做法 |
|---|---|
| 1 拉数据 | agent 调 SocialDataX MCP（`socialdatax-douyin` / `socialdatax-xhs` 等） |
| 2 写一页 | `# 数据回读 <date>` + 表格（平台/物料/主指标/数值/判据/结论） |
| 3 无数据时 | 写 `UNKNOWN` + 「本轮无 L1 数据」，**不许估算** |

**判据**：主指标 ≥ 同条件历史 P80 → 算爆（见 `metrics-taxonomy.md` §2）。样本 n<10 只给相对位置。

**门控 P4**：出现了人工台账字段 → 退回。

## 2. 三档协作模式（简化保留）

| 模式 | 人 | agent |
|---|---|---|
| `copilot` 副驾（默认） | 审 P2 定稿 | 框架驱动，逐阶段产出 |
| `navigate` 主驾 | 指定选题与方向 | 只执行与校验 |
| `autopilot` 自动驾驶 | 只给目标 | 全链自主，仅 2 点确认：目标指标 / 发布前终审 |

**红线（任何模式不许破）**

| 红线 | 原因 |
|---|---|
| **永不代发** | 越权且不可回滚 |
| **永不编造参数与数据** | 缺就写 `UNKNOWN`，编造毁掉整条信任链 |
| **永不写过程文档充数** | 过程文档稀释注意力，是本 CHG 要修的病 |
| **永不跨形态比绝对分** | 三形态权重与基线不同 |

## 4. 门控总表

| 门 | 位置 | 条件 |
|---|---|---|
| 门1 | P0 → P1 | 有 `primary_metric` |
| 门2 | P1 → P2 | 结论带 `source_level`，或已标 `UNKNOWN` |
| 门3 | P2 → P3 | 每条文案有真实评分卡（CLI 输出） |
| 门4 | P3 → 交付 | `mpt.json` 键名合规 + 图文未生成伪命令 + `-f` 用占位 |
| 门5 | P4 | 无人工台账字段；无数据处写 `UNKNOWN` |

## 5. 一句话

> **P0 定靶 → P1 看清 → P2 写稿（主战场）→ P3 出参数 → P4 拿真相。**
> agent 的注意力应该 90% 在 P2，其余四步是它的护栏，不是它的舞台。
