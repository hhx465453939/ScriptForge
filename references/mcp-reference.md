# 侦察协议（S1 唯一承载点）

> 本文件定义运营作战台 **S1 侦察阶段**如何拿数据。闭环阶段见 `references/ops-loop.md`。
>
> 硬要求：**无论宿主是否部署了专业自媒体数据 MCP，都必须能跑完 S1。**
> 有 MCP 就用，没有就降级，降级也要给出带来源层级的结论。

---

## 1. 数据源降级链（三级，逐级回退）

```
L1 专业数据源  →  L2 通用搜索与抓取  →  L3 用户提供 / 本地语料
（有则优先）        （始终可用，必走）      （兜底）
```

**关键认知**：L1 是**加速器**，不是**前提**。把 L1 当前提的 skill，在没装 MCP 的宿主上直接瘫痪——那就不叫工具，叫插件。

---

## 2. L1 · 专业数据源（若有）

| 通道 | 能力 | 用途 |
|---|---|---|
| `socialdatax-xhs` | 小红书笔记/评论/用户/热榜 | 竞品结构、互动中位数、标签分布 |
| `socialdatax-douyin` | 抖音视频/评论/用户/热榜 | 钩子形态、时长分布、爆款共性 |
| 其他已部署平台数据 MCP | 视能力而定 | 同上 |

**使用纪律**：
- 只取**公开可访问**内容，不绕鉴权、不碰私人数据
- 单次侦察总量设上限（建议 ≤50 条/源），避免把侦察做成爬虫
- 每条结果必须记录：来源通道、抓取时间、样本量

---

## 3. L2 · 通用搜索与抓取（必走，不依赖 MCP）

| 通道 | 用途 |
|---|---|
| `open-websearch-local` | 通用网页搜索（优先） |
| `scrapling` | 网页正文抓取（需渲染时用） |
| `bing-search` / `fetch` | 辅助搜索与兜底 |

**S1 必做的三件事，全在 L2 可完成**：

| 任务 | 做法 | 产出 |
|---|---|---|
| 热点扫描 | 搜「近 7/30 天 + 赛道关键词 + 热/爆/争议」；交叉 2 个以上来源 | 热点表（含时效窗口） |
| 竞品采集 | 搜赛道头部内容的公开文本/描述；抓正文后交给五层拆解 | 竞品结构特征表 |
| 受众语言 | 从评论、问答、论坛提取原生表达与真实问题 | 受众痛点词表 |

**交叉验证纪律**：单一来源的热点**不算热点**，至少 2 个独立来源同向才算。

---

## 4. L3 · 用户提供 / 本地语料

- 用户提供的截图、后台数据、口述经验
- 仓库内已有语料：`samples/`、`references/`、历史 `campaigns/*/01-recon.md`

**用法**：作为**补充与校验**，不作为唯一依据下结论。

---

## 5. 来源分级（强制，违反即报告不合格）

| 层级 | 定义 | 可信度 | 使用限制 |
|---|---|---|---|
| `L1` | 平台官方后台/导出、GitHub API、官方开放平台、已部署的官方数据 MCP | 高 | 可直接用于「爆/不爆」判定 |
| `L2` | 第三方工具估算、公开报道、搜索结果聚合 | 中 | **不得单独用于判定**，只能做方向性参考 |
| `L3` | 用户口述、人工观察、主观印象 | 低 | 只能做输入，必须标注 |

**硬规则（对应 `ops-loop.md` 门控 G1）**：

1. `01-recon.md` 里**每个数字**后面必须有 `source_level`
2. 拿不出层级 → 写 `UNKNOWN`，不许写「据说」「网上说」「大概」
3. 用 `L2`/`L3` 数据下的结论，措辞必须降级（「可能」「需进一步验证」），不许用断言

---

## 6. 热点与概念分析（方法，不只是工具）

不是「搜一下就完」，按四步走：

| 步 | 动作 | 判据 |
|---|---|---|
| 1 收集 | 近 30 天赛道相关事件/概念/梗 | ≥8 条 |
| 2 判相关性 | 与我们定位的相关度（高/中/低）+ 理由 | 高相关 ≥2 条才有借势价值 |
| 3 判时效 | 窗口还剩多久（爆发期/平台期/衰退期） | 只剩衰退期的不要借 |
| 4 定角度 | 我们的**差异化视角**（不是复述热点） | 必须有「别人怎么说 vs 我们怎么说」 |

**禁止**：为了蹭热点而扭曲定位。定位（S2）优先于热点。

---

## 7. 竞品采集（抓什么）

| 维度 | 抓什么 | 怎么用 |
|---|---|---|
| 结构 | 钩子类型、段落功能序、CTA 位置 | 用既有五层拆解 + `content-genres.md` 形态矩阵 |
| 密度 | 字数/段数/标签数/时长 | 与自己的对比，找空位 |
| 互动 | 点赞/收藏/评论中位数 | 作为竞品基线（标 `L2`） |
| 空位 | 竞品**都没做**的角度 | 这就是 S2 差异点的来源 |

---

## 8. 禁止事项

| 禁止 | 原因 |
|---|---|
| 编造数据或来源 | 比缺失严重得多，毁掉整条信任链 |
| 绕鉴权、抓私域数据 | 合规红线 |
| 把侦察做成大规模爬虫 | 侦察是取样，不是建库 |
| 单一来源就下结论 | 无交叉验证 |
| 用 `L2`/`L3` 数据宣称「爆了」 | 违反 §5 硬规则 |
| 借热点扭曲定位 | 短期流量换长期账号资产，不划算 |

---

## 9. 输出契约

`01-recon.md` 必须含四块（模板见 `assets/campaign-package.md` §3.2）：

1. 受众（结论 / 证据 / `source_level`）
2. 竞品（结构 / 互动中位数 / `source_level`）
3. 热点与概念（相关性 / 角度 / 时效窗口 / `source_level`）
4. 侦察结论（机会在哪 / 不要碰什么 / 最缺的证据）

**进 S2 的门**：三块齐全 + `source_level` 无空值（门控 G1）。
