# 完形填空模板生成规则与示例

## 概述

完形填空模板是本 skill 的核心交付物之一。它的目标是将爆款文案的**逻辑骨架和表达技巧**保留下来，将与**具体产品绑定的内容**做成占位符，让运营同学只需填入自家产品信息即可直接使用。

> ⚠️ **触发规则:** 所有拆解任务默认输出完形填空模板。测评类/种草类/清单类文案为**必须输出**。

---

## 核心原则

### 保留 vs 留空判定标准

#### ✅ 必须保留的内容（不替换）

| 类型 | 说明 | 示例 |
|------|------|------|
| 转折/连接词 | 文案的逻辑骨架 | "但是""而且""就连""关键" |
| 情绪表达框架 | 制造情绪的句式 | "你不能早点说吗？""这算什么？""真的太XX了" |
| 反问/感叹句式 | 增强冲击力的句式 | "想XX就XX""完全不会XX" |
| 通用金句 | 跨品类通用的表达 | "用户听着爽，买着也爽" |
| 节奏设计 | 排比、递进等修辞结构 | "XX也好，XX也好，XX更好" |
| CTA句式 | 行动号召的标准表达 | "快来直播间安排上" |
| 对比逻辑框架 | 新旧对比的句式结构 | "那我之前一直用XX的" |

#### 📝 必须留空的内容（用占位符）

| 类型 | 说明 | 占位符示例 |
|------|------|------------|
| 产品名称/品类 | 具体的产品指代 | `[______产品名称]` |
| 核心卖点 | 产品特有的功能/优势 | `[______核心卖点]` |
| 具体数据 | 容量、价格、克数等数字 | `[______数据]` |
| 材质/成分 | 产品特有的材料描述 | `[______材质/成分]` |
| 使用场景 | 与产品绑定的具体场景 | `[______使用场景]` |
| 痛点描述 | 品类特有痛点 | `[______痛点]` |
| 用户群体 | 目标人群描述 | `[______人群]` |
| 身份/职业 | 开头钩子中的身份词 | `[______身份]` |

---

## 占位符命名规范

### 格式

使用 `[______描述]` 格式，描述部分使用简洁的中文标签:

- `[______产品名称]` — 具体产品名
- `[______核心卖点]` — 主要卖点
- `[______价格/优惠]` — 价格或优惠信息
- `[______数据]` — 具体数字
- `[______材质/成分]` — 材料
- `[______使用场景]` — 场景描述
- `[______痛点]` — 用户痛点
- `[______功能描述]` — 具体功能
- `[______身份]` — 职业/身份词
- `[______效果]` — 使用效果

### 粒度控制

**粗粒度（推荐默认）:** 每个逻辑单元一个占位符，运营同学一句话填写。

> 示例: `[______核心卖点描述]` → 运营填写"盖子能收纳在侧边"

**细粒度（用户可指定）:** 拆到具体的产品属性，适合需要精确控制的场景。

> 示例: `[______产品部位]都是[______材质]的` → 运营分别填写"杯身""磨砂"

## 标准输出格式

每次生成完形填空模板时，必须包含以下三个部分:

### 1. 填写指南

```markdown
### 📝 填写指南
- 模型名称: [XXXX]
- 共 [N] 个填空处
- 预计填写时间: [X] 分钟
- 建议先准备好:
  1. 产品名称和品类
  2. 3-5个核心卖点
  3. 价格/优惠信息
  4. 1-2个使用场景
```

### 2. 模板正文

使用编号的占位符，方便填写时对应:

```markdown
### 📄 模板正文

[______①身份]能不能不要当[______②相关身份]？[______③核心卖点]，你不能早点说吗？

那我之前一直用[______④旧方案]的，这算什么？

[______⑤功能描述]，还特别[______⑥功能描述]，不容易[______⑦痛点解决]。

...（完整模板）

关键现在新品上市直掉[______㉔价格]，快来直播间安排上。
```

### 3. 填空说明表

每个占位符必须有填写说明和至少一个示例:

```markdown
### 📋 填空说明

| 编号 | 填写内容 | 示例A（原产品） | 示例B（跨品类） |
|------|----------|----------------|----------------|
| ① | 产品相关身份/职业 | 设计师 | 营养师 |
| ② | 相关身份 | 设计师 | 配方师 |
| ③ | 核心卖点描述 | 盖子能收纳在侧边 | 精华能直接加在粉底液里 |
| ... | ... | ... | ... |
```

## 完整示例: 「吐槽安利」模型

### 原始文案（水杯）

> 哑巴能不能不要当设计师？盖子能收纳在侧边，你不能早点说吗？内胆还是白陶瓷覆层的，那我之前一直用不锈钢的，这算什么？咖啡、果汁都能放心装，还特别好清洗，不容易留异味。就连杯身都是磨砂材质的，完全没有掉漆的烦恼。一杯就有500毫升，完全可以满足一天的饮水量。而且杯杯还是自带吸管口设计的，加粗吸管口还可以喝珍珠椰果，想怎么喝就怎么喝。密封性很好，倒置摇晃都不会漏的，出门就这么放在包里也很方便。关键现在新品上市直掉30，快来直播间安排上。

```

[______⑤功能描述]，还特别[______⑥功能描述]，不容易[______⑦痛点解决]。

就连[______⑧产品部位]都是[______⑨材质/特性]的，完全没有[______⑩常见痛点]的烦恼。

而且[______⑭产品特点]还是[______⑮设计特点]的，[______⑯扩展功能]还可以[______⑰使用场景]，想[______⑱]就[______⑲]。

```

## 不同文案类型的完形填空策略

| 文案类型 | 完形填空重点 | 占位符数量建议 |
|----------|-------------|---------------|
| 吐槽安利 | 身份钩子 + 卖点序列 + 价格 | 10-15个 |
| 痛点暴击 | 痛点场景 + 测试数据 + 背书 | 8-12个 |
| 清单收割 | 产品名称 + 每件卖点 + 总价 | 每件3-5个 |
| 测评对比 | 对比产品 + 测试维度 + 结论 | 10-15个 |
| 故事型 | 冲突场景 + 转折产品 + 效果 | 8-12个 |
