# 完形填空模板生成规则与示例

## 概述

完形填空模板是本 skill 的核心交付物之一。它的目标是将爆款文案的**逻辑骨架和表达技巧**保留下来，将与**具体产品绑定的内容**做成占位符，让运营同学只需填入自家产品信息即可直接使用。

> ⚠️ **触发规则:** 所有拆解任务默认输出完形填空模板。测评类/种草类/清单类文案为**必须输出**。

---

## 核心原则

### 保留 vs 留空判定标准

#### ✅ 必须保留的内容（不替换）

| 类型 | 说明 | 示例 |
|------|------|------|
| 转折/连接词 | 文案的逻辑骨架 | "但是""而且""就连""关键" |
| 情绪表达框架 | 制造情绪的句式 | "你不能早点说吗？""这算什么？""真的太XX了" |
| 反问/感叹句式 | 增强冲击力的句式 | "想XX就XX""完全不会XX" |
| 通用金句 | 跨品类通用的表达 | "用户听着爽，买着也爽" |
| 节奏设计 | 排比、递进等修辞结构 | "XX也好，XX也好，XX更好" |
| CTA句式 | 行动号召的标准表达 | "快来直播间安排上" |
| 对比逻辑框架 | 新旧对比的句式结构 | "那我之前一直用XX的" |

#### 📝 必须留空的内容（用占位符）

| 类型 | 说明 | 占位符示例 |
|------|------|------------|
| 产品名称/品类 | 具体的产品指代 | `[______产品名称]` |
| 核心卖点 | 产品特有的功能/优势 | `[______核心卖点]` |
| 具体数据 | 容量、价格、克数等数字 | `[______数据]` |
| 材质/成分 | 产品特有的材料描述 | `[______材质/成分]` |
| 使用场景 | 与产品绑定的具体场景 | `[______使用场景]` |
| 痛点描述 | 品类特有痛点 | `[______痛点]` |
| 用户群体 | 目标人群描述 | `[______人群]` |
| 身份/职业 | 开头钩子中的身份词 | `[______身份]` |

---

## 占位符命名规范

### 格式

使用 `[______描述]` 格式，描述部分使用简洁的中文标签:

- `[______产品名称]` — 具体产品名
- `[______核心卖点]` — 主要卖点
- `[______价格/优惠]` — 价格或优惠信息
- `[______数据]` — 具体数字
- `[______材质/成分]` — 材料
- `[______使用场景]` — 场景描述
- `[______痛点]` — 用户痛点
- `[______功能描述]` — 具体功能
- `[______身份]` — 职业/身份词
- `[______效果]` — 使用效果

### 粒度控制

**粗粒度（推荐默认）:** 每个逻辑单元一个占位符，运营同学一句话填写。

> 示例: `[______核心卖点描述]` → 运营填写"盖子能收纳在侧边"

**细粒度（用户可指定）:** 拆到具体的产品属性，适合需要精确控制的场景。

> 示例: `[______产品部位]都是[______材质]的` → 运营分别填写"杯身""磨砂"

## 标准输出格式

每次生成完形填空模板时，必须包含以下三个部分:

### 1. 填写指南

```markdown
### 📝 填写指南
- 模型名称: [XXXX]
- 共 [N] 个填空处
- 预计填写时间: [X] 分钟
- 建议先准备好:
  1. 产品名称和品类
  2. 3-5个核心卖点
  3. 价格/优惠信息
  4. 1-2个使用场景
```

### 2. 模板正文

使用编号的占位符，方便填写时对应:

```markdown
### 📄 模板正文

[______①身份]能不能不要当[______②相关身份]？[______③核心卖点]，你不能早点说吗？

那我之前一直用[______④旧方案]的，这算什么？

[______⑤功能描述]，还特别[______⑥功能描述]，不容易[______⑦痛点解决]。

...（完整模板）

关键现在新品上市直掉[______㉔价格]，快来直播间安排上。
```

### 3. 填空说明表

每个占位符必须有填写说明和至少一个示例:

```markdown
### 📋 填空说明

| 编号 | 填写内容 | 示例A（原产品） | 示例B（跨品类） |
|------|----------|----------------|----------------|
| ① | 产品相关身份/职业 | 设计师 | 营养师 |
| ② | 相关身份 | 设计师 | 配方师 |
| ③ | 核心卖点描述 | 盖子能收纳在侧边 | 精华能直接加在粉底液里 |
| ... | ... | ... | ... |
```

## 完整示例: 「吐槽安利」模型

### 原始文案（水杯）

> 哑巴能不能不要当设计师？盖子能收纳在侧边，你不能早点说吗？内胆还是白陶瓷覆层的，那我之前一直用不锈钢的，这算什么？咖啡、果汁都能放心装，还特别好清洗，不容易留异味。就连杯身都是磨砂材质的，完全没有掉漆的烦恼。一杯就有500毫升，完全可以满足一天的饮水量。而且杯杯还是自带吸管口设计的，加粗吸管口还可以喝珍珠椰果，想怎么喝就怎么喝。密封性很好，倒置摇晃都不会漏的，出门就这么放在包里也很方便。关键现在新品上市直掉30，快来直播间安排上。

## 不同文案类型的完形填空策略

| 文案类型 | 完形填空重点 | 占位符数量建议 |
|----------|-------------|---------------|
| 吐槽安利 | 身份钩子 + 卖点序列 + 价格 | 10-15个 |
| 痛点暴击 | 痛点场景 + 测试数据 + 背书 | 8-12个 |
| 清单收割 | 产品名称 + 每件卖点 + 总价 | 每件3-5个 |

## 按形态的完形填空规则（video / graphic / text）

> 上面所有规则本质上是**口播（video）**规则。图文与长文的骨架形态不同，不能直接套用。
> 形态判定见 `references/content-genres.md` §2。

### 速查：三形态留空位差异

| 形态 | 必须保留 | 必须留空 | 特有占位位 | 占位符数量 |
|---|---|---|---|---|
| video | 转折词、情绪句式、CTA 句式、节奏设计 | 产品名、卖点、数据、价格 | `[______旧方案]`、`[______负面结果]` | 10-24 个 |
| graphic | 标题公式、分段骨架、emoji 位置、标签类型 | 品类名、人群词、场景、卖点 | **标题公式位 / 首图钩子位 / 正文分段位 / 标签位**（四类必齐） | 标题1 + 分段5-7 + 标签1 |
| text | 论点句式、论证结构、限定语、金句对偶 | 论题、证据数据、结论动词 | `[______主张]`、`[______证据]`、`[______限定条件]` | 8-14 个 |

## 图文（graphic）完形填空规则

### 四条硬规则

1. **四类位置必齐**：标题公式位、首图钩子位、正文分段位、标签位。缺任何一类 = 不合格交付。
2. **标题必须给公式槽**，不只给空：要写明「人群词 + 痛点/场景 + 爽点」的结构要求与字数上限。
3. **正文按段给骨架**，每段一行，并标注该段的功能（场景/痛点/方案/证据/缺点/CTA）。
4. **标签必须给类型组合**（品类词 + 人群词 + 场景词 + 长尾词），并标注数量区间（4-8 个）。

### 标准骨架

```
[______①标题公式槽：人群词 + 痛点/场景 + 爽点，控制在 12-18 字]

[______②首段：一句话结论或场景切入，≤60 字]😮‍💨

[______③第2段：痛点具体化 + 一个真实场景]

[______④第3段：方案/产品出场，说清一个核心机制]

[______⑤第4段：实测证据（数据/时长/对比结果）]

[______⑥第5段：缺点或限定条件（真实感来源）]

[______⑦第6段：CTA（收藏/关注/评论诱饵）]

# [______⑧标签组：品类词 + 人群词 + 场景词 + 长尾词，共 4-8 个]

> ⑨首图钩子（若提供首图描述）：[______画面文字 ≤12 字] + [______视觉重心]
```

### 填写说明表

| 编号 | 填写内容 | 示例A（美妆） | 示例B（家居） |
|---|---|---|---|
| ① | 标题公式槽 | 混干皮亲测｜挖到一瓶不卡粉的粉底液 | 租房党必看｜20平小屋改造清单 |
| ② | 首段切入 | 作为一个从大学就开始踩雷的混干皮…… | 预算八百，我把出租屋改成了我想要的样子 |
| ③ | 痛点+场景 | 鼻翼卡纹、下午发灰 | 空间小、杂物没处放 |
| ④ | 方案+机制 | 乳液质地，靠成膜而不是靠厚 | 上墙收纳，把地面还给活动区 |
| ⑤ | 实测证据 | 持妆8小时，下午三点T区微出油不斑驳 | 改完多出一平米，折叠桌不用时靠墙 |
| ⑥ | 缺点/限定 | 色号偏白，建议选深一档 | 打孔需要房东同意 |
| ⑦ | CTA | 已回购第二瓶，空瓶在第4张图 | 清单放评论区了，自己抄 |

| ⑨ | 首图钩子 | 「8小时实测」+ 前后对比分屏 | 「800元改造」+ 改造前后俯拍 |

### 图文特有反模式

- 正文写成口播流水句（一逗到底、无分段）→ 必改
- 标题与首图说同一句话 → 浪费一个钩子位
- 标签只有品类词（无人群/场景/长尾）→ 拿不到长尾流量

## 长文（text）完形填空规则

### 四条硬规则

1. **保留论证骨架**：主张句 → 理由 → 证据 → 限定 → 反驳 → 结论。这是长文的承重墙。
2. **限定语必须留位**：`[______限定条件]` 是长文可信度的来源，不能省。
3. **结论金句化**：结尾要留一个可被引用的对偶/断言槽。
4. **小标题按节给**，不按句给。

### 标准骨架

```
## 一、[______①核心问题/现象]

[______②铺垫一句，不超过两行]

但真正的机制不是 [______③表面归因]，而是 [______④真实归因]。

## 二、[______⑤第一层论证小标题]

[______⑥主张句]。理由有三点。

第一，[______⑦理由1]。第二，[______⑧理由2]。第三，[______⑨理由3]。

[______⑩证据：数据/实测/案例]

当然，[______⑪限定条件：样本有限/场景限制/需谨慎推广]。

## 三、[______⑫常见反驳]

有人认为 [______⑬反方观点]。这个批评有道理。

我的回应是：[______⑭回应逻辑]。

## 四、结论

说到底，[______⑮核心判断的金句化表达]。
```

### 填写说明表

| 编号 | 填写内容 | 示例A（内容创作） | 示例B（自律方法） |
|---|---|---|---|
| ① | 核心问题 | 内容创作靠灵感吗 | 自律靠意志力吗 |
| ② | 铺垫 | 很多人把它理解为天赋问题。 | 大多数人认为自律靠咬牙。 |
| ③ | 表面归因 | 灵感 | 意志力 |
| ④ | 真实归因 | 结构 | 启动成本 |
| ⑥ | 主张句 | 内容不是写给自己看的，是写给推荐系统的 | 自律不是对抗自己，是设计自己 |
| ⑩ | 证据 | 实测两百条笔记，>20字点击率降三成 | 把目标拆到一页，坚持率提升 |
| ⑪ | 限定 | 样本仍有限，平台算法会迭代 | 对低动机任务仍需外部约束 |
| ⑮ | 结论金句 | 与其追逐灵感，不如沉淀结构 | 与其对抗自己，不如设计自己 |

### 长文特有反模式

- 开头「随着……的发展」→ 必改
- 全篇无小标题 → 跳读者直接退出
- 只有主张没有证据（证据/论点比 < 1）→ 说服力崩塌
- 零限定语 → 招反驳与举报
