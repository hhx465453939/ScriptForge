# 视频脚本模型库

本文件收录经过拆解验证的可复用脚本模型。每个模型包含框架结构、核心逻辑、适用品类和完形填空骨架。

> **持续更新规则:** 每次拆解出新的脚本模型时，对照本库。如为已有模型的变体，记录变体特征；如为新模型，按以下格式新增。

## 模型 1: 吐槽安利

**来源:** 水杯带货视频拆解
**内容类型:** 冲突类带货
**适用品位:** 全品类通用，尤其适合有明确对比场景的产品

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|------|------|----------|
| 第一层 | 情绪吐槽钩子 | 用"吐槽"制造冲突，引发好奇（"什么东西这么气人？"）|
| 第二层 | 后悔对比+产品优势 | 建立新旧对比，制造后悔感，顺势引出产品卖点 |
| 第三层 | 场景延展+体验证言 | 用具体场景让用户脑补使用画面，增强代入感 |
| 第四层 | 价格暴击+行动指令 | 降价信息制造紧迫感，直接引导下单 |

### 核心逻辑

1. **吐槽钩子制造冲突:** "哑巴设计师"比"这款水杯真好用"冲击力强10倍，用户好奇"什么东西这么气人"
2. **后悔感建立对比:** "那我之前用不锈钢的，这算什么？"——用户代入"我也用错了"，比自夸有效
3. **痛点颗粒度极细:** 每个卖点对应真实痛点：掉漆、留味、漏、不能喝奶茶
4. **场景精准狙击:** "加粗吸管口还可以喝珍珠椰果"直接让目标人群脑补使用画面

### 完形填空骨架

```
[______身份]能不能不要当[______相关身份]？[______核心卖点]，你不能早点说吗？

那我之前一直用[______旧方案]的，这算什么？

[______功能1]，还特别[______功能2]，不容易[______痛点解决]。

就连[______产品部位]都是[______材质/特性]的，完全没有[______常见痛点]的烦恼。

一[______量词]就有[______数据]，完全可以[______效果]。

而且[______产品特点]还是[______设计特点]，[______扩展功能]还可以[______使用场景]，想[______]就[______]。

[______质量特性]很好，[______测试动作]都不会[______负面结果]的，[______场景]也很方便。

关键现在新品上市直掉[______价格]，快来直播间安排上。
```

### 已验证品类

| 品类 | 产品 | 效果 |
|------|------|------|
| 水杯 | 保温杯 | 原始案例，销量千单+ |
| 食品 | 即食鸡胸肉 | 仿写验证通过 |
| 美妆 | 养肤粉底液 | 仿写验证通过 |

## 模型 2: 痛点暴击

**来源:** 常见测评类视频拆解
**内容类型:** 测评/对比类
**适用品类:** 功能性强的产品（护肤品、家电、3C数码）

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|------|------|----------|
| 第一层 | 痛点共鸣钩子 | 直击用户真实痛点，引发"就是我"的认同 |
| 第二层 | 方案悬念 | 引出产品但不说透，制造"到底是什么"的好奇 |
| 第三层 | 实测展示+对比 | 用具体数据和场景展示产品效果，新旧对比 |
| 第四层 | 信任背书+CTA | 用权威/数据/社会证明建立信任，引导下单 |

### 核心逻辑

1. **先痛后解:** 先让用户感受到痛点，再给出解决方案，效果远胜于直接推销
2. **数据说话:** 用具体数字替代模糊描述，增强可信度
3. **场景化验证:** 在具体使用场景中展示效果，而非空泛夸赞

### 完形填空骨架

```
[______痛点场景/困扰]，真的太[______负面感受]了。

直到我发现了这个[______产品名称]，[______悬念式效果描述]。

[______具体测试/使用场景]，[______数据/对比结果]。

而且[______权威背书/认证]，[______用户评价/销量数据]。

关键现在[______优惠信息]，快来[______行动指令]。
```

## 模型 3: 清单收割

**来源:** 常见好物推荐类视频拆解
**内容类型:** 种草/推荐类
**适用品类:** 适合多SKU展示、套装推荐、场景搭配推荐

### 框架结构（3层）

| 层级 | 功能 | 逻辑说明 |
|------|------|----------|
| 第一层 | 场景/人群钩子 | "XX人必备""租房党看过来"——精准圈人 |
| 第二层 | 逐条罗列+卖点 | 每件产品一个痛点+一个卖点，节奏紧凑 |
| 第三层 | 总结+行动指令 | 汇总价值，制造紧迫感，引导下单 |

### 核心逻辑

1. **精准圈人:** 开头直接筛选目标用户，非目标用户划走但目标用户必留
2. **数量冲击:** "N件好物"比单件推荐信息量大，完播率更高
3. **节奏感:** 逐条罗列形成固定节奏，用户形成预期

### 完形填空骨架

```
[______人群/场景]，这[______数量]件好物你必须知道。

第一件，[______产品名称]。[______痛点场景]，用它[______解决方案]。

第二件，[______产品名称]。[______痛点场景]，用它[______解决方案]。

第三件，[______产品名称]。[______痛点场景]，用它[______解决方案]。

这[______数量]件加起来才[______价格]，赶紧[______行动指令]。
```

## 模型 4: 圈人清单（graphic / 图文）

**来源:** 小红书好物盘点类图文拆解
**形态:** graphic｜**内容类型:** 种草/清单
**适用品类:** 多 SKU、场景套装、租房/通勤/学生党集合推荐

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|---|---|---|
| 第一层 | 人群圈定标题 | 标题就是一个筛选器：「XX人必备」，非目标用户不进，目标用户必点 |
| 第二层 | 场景痛点开头 | 一段一个具体场景，让读者对号入座 |
| 第三层 | 逐件罗列 + 一件一卖点 | 每件产品一个痛点 + 一个解决方案，节奏固定 |
| 第四层 | 总价 + 标签收束 | 汇总价值，用标签吃长尾搜索 |

### 核心逻辑

1. **标题即筛选器:** 图文的点击发生在信息流，圈人越准，点击率越高、跳出越低
2. **分段的呼吸感:** 1-3 行一段 + emoji 作为视觉锚点，对抗移动端划走
3. **标签类型组合:** 品类词拿曝光、人群词拿精准、长尾词拿长尾搜索

### 完形填空骨架

```
[______①人群/场景]｜[______②数量]个让我[______③爽点]的[______④品类]

[______⑤首段：一句话结论或场景切入]😮‍💨

第1个：[______⑥产品名]——[______⑦痛点]，用它[______⑧解决方案]
第2个：[______⑨产品名]——[______⑩痛点]，用它[______⑪解决方案]
第3个：[______⑫产品名]——[______⑬痛点]，用它[______⑭解决方案]

[______⑮缺点/限定，真实感来源]

这三件加起来才[______⑯总价]，[______⑰CTA]

# [______⑱标签组：品类+人群+场景+长尾，4-8个]
```

## 模型 5: 亲测打脸（graphic / 图文）

**来源:** 小红书测评类图文拆解
**形态:** graphic｜**内容类型:** 测评/种草
**适用品类:** 美妆、个护、小家电、3C（需有可感知效果的品类）

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|---|---|---|
| 第一层 | 亲测 + 结论标题 | 「亲测一个月」+ 具体结论，用时间成本换信任 |
| 第二层 | 预期违背开头 | 「一开始完全不信」——先降低商业感 |
| 第三层 | 上脸/上手实证 | 具体到质地、时长、对比结果 |
| 第四层 | 缺点 + 复购证明 | **缺点是最好的信任锚**，再给回购/空瓶证据 |

### 核心逻辑

1. **先自曝怀疑:** 「我不信」比「我推荐」可信度高得多，因为它反常于带货语境
2. **缺点必须真:** 图文的收藏率高是因为「敢说禁」，无缺点的测评不算测评
3. **复购即证据:** 「已回购第二瓶/空瓶在第N张图」比任何参数都硬

### 完形填空骨架

```
[______①亲测时长]｜[______②具体结论标题]

作为一个[______③肤质/使用背景]，我对[______④品类]的要求真的很低：[______⑤三条硬要求]

[______⑥产品名]是我[______⑦谁]塞给我的，[______⑧一开始的怀疑理由]

结果[______⑨第一次使用的具体反转细节]✨

[______⑩实测数据：时长/对比/数值]

唯一的缺点是[______⑪真实缺点 + 适配建议]。

[______⑫价格]，我已经[______⑬复购/空瓶证据]📷

# [______⑭标签组]
```

## 模型 6: 结论前置（text / 长文）

**来源:** 公众号十万加长文拆解
**形态:** text｜**内容类型:** 观点/分析
**适用品类:** 方法论、行业观察、认知类话题

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|---|---|---|
| 第一层 | 结论前置 | 前三段给完核心判断，因为长文读者是跳读的 |
| 第二层 | 三点归因 | 「理由有三点」给结构感，降低阅读成本 |
| 第三层 | 实测证据 | 每个论点配可核查的证据，证据/论点比 ≥ 1 |
| 第四层 | 反驳 + 限定 + 金句收束 | 先自曝质疑再回应，显可信；结尾给可引用金句 |

### 核心逻辑

1. **结论前置是对跳读的投降:** 不给结论，读者就到别处去了
2. **限定语是可信度来源:** 无条件断言招反驳，「样本有限」反而显得诚实
3. **可被引用的句子决定转发率:** 段尾与文末的对偶句是传播单元

### 完形填空骨架

```
[______①核心问题]

很多人把[______②问题]理解为[______③表面归因]，但它的本质是[______④真实归因]。

理由有三点。第一，[______⑤理由1]。第二，[______⑥理由2]。第三，[______⑦理由3]。

## 二、[______⑧论证小标题]

我[______⑨实测动作/样本量]。结果显示，[______⑩具体数据结果]。

当然，[______⑪限定条件]。

## 三、[______⑫常见反驳]

有人认为[______⑬反方观点]。这个批评有道理。

我的回应是：[______⑭回应逻辑]。

## 四、结论

说到底，[______⑮金句：不是A，而是B]。
```

## 模型 7: 反常识立论（text / 长文）

**来源:** 知乎高赞回答拆解
**形态:** text｜**内容类型:** 观点/反驳
**适用品类:** 争议话题、行业误区、认知纠偏

### 框架结构（4层）

| 层级 | 功能 | 逻辑说明 |
|---|---|---|
| 第一层 | 立一个可争论的判断 | 不铺垫背景，第一句就是立场，逼读者选边 |
| 第二层 | 先承认主流看法 | 「大多数人认为」——把对方立场说透，才显得不是树立稻草人 |
| 第三层 | 机制层解释 | 从「该不该」拉到「为什么」，避开道德争论进入可论证区域 |
| 第四层 | 反方最强论点回应 | 不回避反论，主动接住最硬的那一条 |

### 核心逻辑

1. **可争论 = 可互动:** 让读者想留言反驳，互动率直接拉高
2. **先扬后破:** 承认主流看法能降低防御，也避免被指「抬杠」
3. **机制解释是护城河:** 只讲「该不该」是情绪，讲到「为什么」才是内容

### 完形填空骨架

```
关于[______①话题]，我有不同的看法。

大多数人认为[______②主流观点]，但真正的机制是[______③机制解释]。

第一，[______④机制点1]。不是[______⑤表面动作]，而是[______⑥真实动作]。
第二，[______⑦机制点2]。
第三，[______⑧机制点3：允许失败/例外]。

有人会反驳说[______⑨反方最强论点]。这一点我必须承认：[______⑩承认的部分]。

但即便[______⑪退一步的前提]，[______⑫仍然成立的理由]。

说到底，[______⑬金句：与其A，不如B]。
```
