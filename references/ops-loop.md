# 运营作战台 · 八阶段闭环

> 本文件是**闭环的唯一承载点**。阶段划分、门控、协作模式只在这里定义，其他文件只引用。
>
> 核心立场：项目要的不是「做出爆款」，是**搭台子**——
> 让有能力的运营者坐主驾，让新手坐副驾（框架替他开），让 agent 在自动驾驶档也能守规矩。

---

## 0. 全图

```
              ┌──────────────────────────────────────────────┐
              │  S0 定标  要赢什么指标？（没有指标不许开工）    │
              └───────────────────┬──────────────────────────┘
                                  ▼
   ┌─────────────────────────────────────────────────────────┐
   │  S1 侦察   受众 / 竞品 / 热点 / 概念    [门控 G1: 标来源]  │
   ├─────────────────────────────────────────────────────────┤
   │  S2 定位   差异化 + 「不做什么」        [G2: 有结论]      │
   ├─────────────────────────────────────────────────────────┤
   │  S3 选题   候选池 → 四维打分 → Top-N   [G3: 有排序]      │
   ├─────────────────────────────────────────────────────────┤

   ├─────────────────────────────────────────────────────────┤

   ├─────────────────────────────────────────────────────────┤

   └───────────────────┬─────────────────────────────────────┘

              ┌──────────────────────────────┐

```

**关键**：S8 必须回流到 S1。不回流，这就是一个断掉的链，不是闭环。

## 1. S0 定标（goal）

**目的**：把「帮我运营火」翻译成可判定的目标。

**必须产出的字段**（写进 `00-brief.md` 的 frontmatter）：

```yaml
campaign: <slug>
obj_type: repo | content | product | personal
primary_metric: <唯一胜负指标>
secondary_metrics: [ ... ]
window: {start: , end: }
baseline: {p50: , p80: , n: } | BASELINE_MISSING
judge: "primary >= baseline.p80"
mode: copilot | navigate | autopilot
resources: {人: , 预算: , 产能: <每周可发布条数>}
constraints: [ 平台限制 / 合规 / 不能做的事 ]
```

**动作**：
1. 判定 `obj_type`（项目/账号/产品/个人）
2. 定 `primary_metric`（唯一！想要两个就拆两个 campaign）
3. 查历史基线；没有就写 `BASELINE_MISSING` 并声明本次为「基线采集战役」
4. 定窗口与资源边界（**产能是最硬的约束**：每周能发几条，决定选题池大小）

**输出**：`00-brief.md`

**门控 G0**：`obj_type` 或 `primary_metric` 缺失 → **禁止进入 S1**。

**常见失败**：用户说"想火"就开工写文案 → 产出无法评判 → 下一轮还是从零开始。

---

## 2. S1 侦察（recon）

**目的**：搞清楚「谁在看、别人在做什么、现在什么在热」。

**动作**（三块，缺一不可）：

| 块 | 要拿到什么 | 数据源 |
|---|---|---|
| 受众 | 目标人群画像、他们的问题与语言 | L1 平台数据 / L2 公开报告 |
| 竞品 | 同赛道的头部内容结构、差异化空位 | 抓取 + 结构拆解（用既有五层拆解） |
| 热点 | 近 7–30 天的热点概念、可借势的梗与事件 | 搜索 + 热点榜 |

**产出**：`01-recon.md`，含三块结论 + 每条数据的 `source_level`。

**门控 G1**：**没有 `source_level` 标注的数据不许出现在报告里**。
未知就写 `UNKNOWN`，不许写"据说"。

**降级链**（详见 `references/mcp-reference.md`）：

```
L1 专业自媒体数据 MCP（若有）
 → L2 通用搜索 + 网页抓取（必做，不依赖 MCP 是否存在）
 → L3 用户提供 / 本地已有语料
```

**关键**：无论有没有专业 MCP，**都必须能跑完 S1**。这是硬要求。

---

## 3. S2 定位（position）

**目的**：找出「我们和别人的差别」，以及「我们不做什么」。

**动作**：
1. 用 `viralmath.align` 的 JS 散度量化「我方用词/结构与竞品均值的距离」
2. 用 `assets/` 的人设卡明确：语气、禁区、常用模型、更新节奏
3. **写出「不做什么」**——这一项最容易被跳过，但它是定位真正的价值

**产出**：`02-positioning.md`

**结构**：
```
我们是谁：<一句话>
我们不是谁：<主动放弃的人群/风格>
差异点（≤3 条，每条可被验证）：
  D1: <差异> ← 证据：<竞品缺失点 + 我方证据>
  D2: ...
不做什么：<明确排除项>
```

**门控 G2**：无差异点（或差异点无法被验证）→ 不许进 S3。

---

## 4. S3 选题（backlog）

**目的**：把无限选题收敛成「本周该做的 N 条」。

**四维打分（冻结）**：

```
score = 0.35·需求强度 + 0.25·(1-竞争密度) + 0.20·可产性 + 0.20·指标契合
```

| 维 | 定义 | 怎么估 |
|---|---|---|
| 需求强度 | 目标人群有多想知道 | 搜索量/提问频率/竞品互动中位数（标来源层级） |
| 竞争密度 | 这条赛道有多挤 | 同题内容数量 + 头部质量 |
| 可产性 | 我们能不能做出来 | 受 `resources.产能` 约束（做不出来的直接 0） |
| 指标契合 | 这条内容天然容易拿主指标吗 | 例：涨粉目标下，"工具体验"契合高；"行业吐槽"契合低 |

**产出**：`03-backlog.md`，候选 ≥12 条，带四维分数与总分，取 Top-N（N = 产能）。

**门控 G3**：没有四维打分的候选池 → 不许进 S4。**"我觉得这个会火"不算打分。**

---

## 5. S4 生产（produce）

**目的**：把选题做成可发布的文案。

**动作**：
1. 逐条按 `content-genres.md` 判定形态（graphic / video / text）
2. 从 `script-models.md` 选模型（7 个现有模型中选，或提炼新模型）
3. 套 `fill-blank-guide.md` 骨架成稿
4. **必跑量化评分卡**：`python scripts/viral_score.py --file <稿> --json`
5. 只看 `weaknesses` 前 2 项定点改，再跑一次，记录变化

**产出**：`04-scripts/<genre>-<NN>.md`，每份含：
- 文案全文
- 所用模型名
- 量化评分卡（七维 + 综合分 + 95% CI + 短板）
- 迭代记录（改了什么、分数怎么变）

**门控 G4**：无评分卡 → 不许进 S5。

**注意**：评分卡只说明**结构强度**，不等于会爆。见 `metrics-taxonomy.md` §0 的分工说明。

---

## 6. S5 组装（assemble）

**目的**：把文案变成一整套**可直接执行**的物料。

**四类产出**（缺一即不合格）：

| 产出 | 文件 | 规格 |
|---|---|---|
| 文生图提示词 | `05-assets/image-prompts.md` | 12 字段冻结，见 `assets/prompt-spec.md` |
| 文生视频提示词 | `05-assets/video-prompts.md` | 11 字段冻结 |
| 可直接粘贴文案块 | `05-assets/copy-blocks.md` | 标题/正文/标签/字幕/评论区引导，按平台分组 |
| HTML 设计文件 | `05-assets/html/` | 落地页/长图/信息卡；纯静态、无外部依赖 |

**每条提示词必须标**：`platform`（哪个平台）+ `model`（用哪个模型族/型号）+ `params`（画幅/时长/种子）。

**门控 G5**：缺 `platform` 或 `model` → 不许进 S6。

**边界**：本阶段**只出规格与提示词**，不生成实际图片/视频（生成交下游工具或人）。

---

## 7. S6 排期（schedule）

**目的**：定「哪天、哪个渠道、发哪个变体」。

**产出**：`06-schedule.md`

| 日期 | 渠道 | 物料文件 | 变体（改了什么） | 预期 | 备注 |
|---|---|---|---|---|---|

**变体纪律**：同一选题的多个变体**只改一个变量**（钩子 / 标题 / CTA / 首图），否则回填无法归因。

**注意**：只在建议层——**发布动作由人执行**（见 §9 红线）。

---

## 8. S7 回填（measure）

**目的**：拿到真相。这是整条链唯一的「现实检验」环节。

**动作**：按 `assets/publish-ledger.md` 填表，字段见 `metrics-taxonomy.md` §4。
**关键必填**：`source_level`、`baseline_at_publish`、`hypothesis_id`。

**门控 G6**：无回填 → 不许进 S8。

---

## 9. S8 校准（calibrate）

**目的**：让下一轮更准。**不回流到 S1 的校准是无效校准。**

**动作**（四件）：

1. **判定**：按 `metrics-taxonomy.md` §2 算 P80 与该条的分位 → 爆/未爆
2. **验假设**：逐条检查假设台账（`assets/publish-ledger.md` 下半部）里的假设，标 `支持的/被否证的/证据不足`
3. **重估基线**：把新数据并入历史序列，重算 P50/P80/n
4. **改尺子**（谨慎）：若某维度与实际结果长期不相关，标注「本维度待重估」——但**不许一次改多个**，否则无法归因

**产出**：`08-review.md`

**回流的三个具体动作**：
- 更新 `00-brief.md` 的 `baseline`
- 把「被否证的假设」写进下一轮 S2 的注意事项
- 把「表现超预期的结构」补进 `script-models.md` 的「已验证品类」

## 10. 三档协作模式（冻结）

| 模式 | 谁决策 | agent 干什么 | 确认点 |
|---|---|---|---|
| **副驾** `copilot`（默认） | 人 | 框架驱动，逐阶段产出 | 每阶段末 1 次 |
| **主驾** `navigate` | 人（强控） | 只执行与校验，不自行判断方向 | 有冲突时提问 |
| **自动驾驶** `autopilot` | agent（在边界内） | 全链自主推进 | 仅 3 点 |

### autopilot 的 3 个确认点（不可省）

1. **目标指标确认**：`obj_type` + `primary_metric` 定完，开工前问一次
2. **资源边界确认**：产能/预算/时间窗，问一次
3. **发布前终审**：物料包齐了，把「要发什么、发哪、什么时候」列给人看，等人点头

### 红线（任何模式都不许破）

| 红线 | 原因 |
|---|---|
| **永不代发** | 越权且不可回滚 |
| **永不编造数据** | 缺失写 `UNKNOWN`，编造毁掉整条信任链 |
| **永不跳门控** | 跳过 = 闭环退化为链，S8 无法归因 |
| **永不跨形态比绝对分** | 三形态权重与基线不同 |

## 11. 门控总表（一页速查）

| 门 | 位置 | 条件 | 不满足时 |
|---|---|---|---|
| G0 | S0 → S1 | 有 `obj_type` + `primary_metric` | 阻断，回去问 |
| G1 | S1 → S2 | 每条数据有 `source_level` | 阻断，补标注或写 `UNKNOWN` |
| G2 | S2 → S3 | 差异点 ≤3 且可验证 | 阻断，重做定位 |
| G3 | S3 → S4 | 候选池有四维打分与排序 | 阻断，补打分 |
| G4 | S4 → S5 | 每份文案有量化评分卡 | 阻断，跑 `viral_score.py` |
| G5 | S5 → S6 | 每条提示词有 `platform` + `model` | 阻断，补适配 |
| G6 | S7 → S8 | 回填表有数据且带 `source_level` | 阻断，先回填 |

## 13. 一句话总结

> **S0 定靶 → S1 看清 → S2 定差异 → S3 收敛 → S4 做出来 → S5 变成资产 → S6 排出去 → S7 拿真相 → S8 变聪明 → 回到 S1。**

每一环都能被判据卡住，每一份产出都能被回填追责。这就是「台子」。
